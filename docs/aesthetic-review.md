## 逐页判读与问题

### 1. 群聊（light-chat / dark-chat / light-approval-card / dark-approval-card）

**现状判读**：三栏构图（树 268px / 消息流 / 右栏 400px）稳定，眯眼测试下层次成立：卡片面 vs `--bg` 画布分离清晰。用户气泡 accent 蓝底 + 深字，bot 气泡灰面，右栏卡片群与消息流留白分隔明确。灰度测试下用户/消息身份仍可辨（明度差足够）。

**问题**：
- **P1｜消息流节奏单调**：连续多条同发送者气泡每条都独立渲染 `You 11/02 22:44` 时间戳行 + 全宽 63% 气泡，5 条造数消息形成 5 组完全等高的蓝色块，眼动没有落点（任何一条都不比另一条重要）。修法：同发送者连续消息合并为一个气泡组——组内只在首条显示头像与时间戳（CSS 层面：气泡 margin-top 从 44px 级收到 8px 级，组间保持 24px 级）；气泡 `max-width` 用 `72ch` 上限替代百分比，长句折行更可读。
- **P2｜右栏「活跃任务」行 meta 挤压**：`进行中 AUD2-5 AUD2 前置任务：依赖… >` 一行里状态词、编号、标题、箭头四个信息挤在同一灰度层级，标题被省略号截到只剩 5-6 字。修法：编号用 `--fs-caption` + `--mono`，标题独立一行 `--fs-small` `--ink-2`，状态色只保留 6px 圆点。
- **P2｜审批卡片宽度突兀**：`light-approval-card` 里审批卡仅 ~300px 宽、左对齐挂在消息流最左，与上下 ~900px 宽的气泡形成宽度断崖，且左侧 accent 竖条是全页唯一的「信件边框」式样。修法：审批卡宽度对齐气泡体系（同 `max-width:72ch` 或至少 50%），「允许一次/拒绝」按钮对与其他消息操作 chip 同一规格。

### 2. 单聊 / 调度（light-solo-chat / dark-solo-chat）

**现状判读**：结构同群聊，右栏切换为调度对象/在办任务/子智能体等 7 张卡，信息密度明显高于群聊右栏但仍能读，卡片群节奏一致。

**问题**：
- **P2｜「思考过程」chip 悬空**：每条 bot 气泡下方挂一个独立灰 chip，与气泡间距 ~8px 但左缘缩进不一致（chip 缩进到头像右侧，气泡从更右开始），对齐轴混乱。修法：chip 与气泡左缘对齐同一 x 轴（同 padding-left），或并入气泡 footer 行。
- **P2｜右栏卡高度不齐**：调度对象卡 ~90px、待办任务卡 ~90px、子智能体卡 ~150px（说明文字长），一列卡片高度差大且无分组标题，扫读时「哪张卡是什么」靠读内容猜。修法：给右栏每张卡保留 `empty-state` 式图标头或统一 `min-height:96px`，说明类长文收进折叠。

### 3. 任务面板（light-tasks / dark-tasks）

**现状判读**：分组折叠列表结构清楚，状态圆点色阶（灰/蓝/橙/红/绿）可用。但整页是全站信息密度最失衡的一页：一屏 1000px 内容区只渲染 5 行任务，行与行之间是 ~60px 的组头 + 大留白，页面下方 45% 是纯 `--bg` 空白；每行从状态 icon（x≈340）一直拉到右缘 meta（x≈1560），单行长度超过 1200px，远超可读行宽。

**问题**（D-60 P1-1/P1-4 已列功能与空白块问题，此处只列审美）：
- **P1｜行宽失控**：任务行无 `max-width`，meta（「空闲 未指派」）被推到与标题相距 >900px 的位置，行内元素间的关联性断裂（title 与它的状态在视觉上是两个页面角）。修法：列表容器加 `max-width: 960px`（或 `min(960px, 100%)` 居中），meta 列固定宽 `120px` 右对齐，行 hover 时才显 meta 亦可。
- **P2｜组头与行内状态图形语言不一致**：组头用 8px 实心圆点（`--star`/`--green` 等色），行内用 16px 描边 icon（时钟/勾），同一状态在两级是两套图形。修法：组头圆点换成与行内 icon 同族的 12px 缩小版，或统一为「点+色」单语言。

### 4. 成员 tab（light-members / dark-members）

**现状判读**：单卡居中，卡片内部 5 行信息全部水平居中、行距均质（头像/名字/角色/model/状态/用量），眯眼测试没有第一落点——每行权重相同。绿色「空闲中」文字在 light 下 3.24:1 不达标。

**问题**：
- **P1｜状态行绿色小字不达标 + 双状态冗余**：light `--green` 3.24:1（dark 10.67:1 无问题）；且「● 空闲」与「● 空闲中」两行语义重复（D-60 P2-3 / D-65 已派合并）。审美角度补一条：合并后状态建议用 pill（`--green-wash` 底 + `--ink` 字 + 6px 绿点），pill 底色承载语义、文字保持 ink 色即可同时解决对比度与层级，不要用 `--green` 直接做 <15px 文字色。修法：`.member-status-text { color: var(--ink-2); }`，语义色只留在点/底上。
- **P2｜卡片内容居中堆叠无轴**：model 名 `deepseek/deepseek-flash` 用 mono 居中夹在角色与状态之间，与全站「左轴列表」语言相悖。修法：卡内改左对齐两列（label `--fs-caption` `--ink-3` / value `--fs-small` `--ink`），头像行保持居中即可。

### 5. 总览bots（light-bots-overview / dark-bots-overview）

**现状判读**：3 列卡片网格、间距一致、卡片内「头像+名/角色/meta/操作行」层级清楚，是全站卡片语言执行得最好的一页。bot 识别色（teal/blue/violet/amber/coral/pink）作头像底,身份可辨。

**问题**：
- **P2｜操作按钮三连全部同级**：`配置 / 调度 / 归档` 三个 outline 按钮同权重并排，但「归档」是低频且偏破坏性的动作。修法：归档降级为 icon-only ghost 按钮或收进 ⋯ 菜单，`配置` 保持主操作。
- **P2｜统计行「0 任务 · 0 记忆 · 24 次成功」全灰**：三个数字与标签同灰度（`--ink-3`），数字没有比标签重。修法：数字用 `--ink` + `--fs-body`，标签保持 `--fs-caption` `--ink-3`。

### 6. 技能（light-skills-small / dark-skills-small）

**现状判读**：单列长卡流，全页渲染高度 11854px、40+ 张卡连续堆叠，无分组锚点；卡片内标题、描述、路径三段近同灰度。裁剪测试：页首说明区 + 每卡「查看/查看仓库」双按钮可砍。

**问题**：
- **P1｜长列表无导航层级**：40+ 卡一列到底，滚动定位纯靠肌肉记忆；卡片标题是唯一层级信号。修法：① 卡片改 2 列 grid（`grid-template-columns: repeat(auto-fill, minmax(420px, 1fr)); gap: 16px`），页高约减半；② 页首加锚点分组（内置/团队/共享），sticky 分组头用 `--fs-caption` eyebrow。
- **P2｜双「查看」按钮同权重**：每卡右下「查看 / 查看仓库」两个 outline 按钮同尺寸同色。修法：仓库链接降为文字链接（`--accent-text` 无底）。

### 7. 记忆（light-memory / dark-memory）

**现状判读**：空态（图标 + 「还没有记忆」+ 说明 + 按钮）居中，与进化提案空态同构——空态语言全站统一，这是优点。

**问题**：
- **P2｜空态垂直位置偏高**：空态组整体从内容区顶部 ~1/3 处开始（图标 y≈240/1000），下方留 60% 空白，重心不稳。修法：`.empty-state` 外层容器 `min-height: calc(100% - 120px)` + `place-content: center`，让空态落在视口几何中心。
- 造数注：AUD2 的 create_memory 写入未在列表出现（可能 action 名不符），本页以空态入档；有数据形态待补拍。

### 8. 用量统计（light-usage / dark-usage）

**现状判读**：4 张 KPI 卡数字 `--fs-display` 级、明度权重最高，第一眼落在「74.3k」，层次成立；柱图与分模型/分 Bot/分项目卡片网格节奏与总览bots 一致。

**问题**：
- **P1｜分项目行首暴露 raw id**：`prj_9136b9ede3…` mono 灰字直接作行标签，与下方「AUD2 审美走查…」可读名混排在同一列，既是噪声（开发元信息）又破坏行的韵律（两行标签一长一短、字体不同）。修法：只显示项目名，id 收进 `title` 属性；无名的项目显示「未命名项目」。
- **P2｜单柱柱图重心失衡**：近 14 天只有 1 根柱时，柱子贴在图表中线偏左、两侧大面积空白，图表框高度 ~200px 与信息量不匹配。修法：数据点 < 3 时降图表高度到 120px 或改为数字卡（「11/02 · 74.3k」）。
- **P2｜口径说明行游离**：`口径：全局视图，不随当前群聊/单聊上下文变化。` 是全页唯一裸露在卡片外的文字，无 eyebrow 结构。修法：并进 KPI 区作 caption 行，或移到页头 subtitle。

### 9. 终端（light-terminal / dark-terminal）

**现状判读**：D-66 立项的图标撑屏问题在当前构建已不复现（输出区为正常高度黑块），D-66 要求的标题栏（路径）、输入行（提示符+快捷键+执行按钮）、历史命令卡三段结构已具备。但 dark 主题下这一页的「井」消失了：`--console-bg` #12141c 与 dark 卡面 #191b26 的面间对比实测 **1.08:1**，输出区、输入区、历史卡三块融成一片，只剩 1px `--line` 缝。浅色模式下黑井与全站浅色面对比强、层级最好；dark 下反而最弱——井存在的意义（「唯一一块暗面」）在 dark 里失效。

**问题**：
- **P1｜dark 下 console 井层级失效**：修法（二选一）：① dark 下把 `--console-bg` 提到 `#0c0e15`（与 surface 的比值升至约 1.3:1）并保留 `--console-line` 内描边；② 输出区维持现色但外层加 `box-shadow: inset 0 0 0 1px var(--console-line)` + 输入区行用 `--console-bg-2` #1a1d27 拉开输入/输出两段。推荐 ②，不动 token 体系。
- **P2｜历史命令卡与终端卡等宽双卡竖排，但没有视觉从属**：历史卡是普通浅色卡，紧贴黑井下方，两卡圆角/阴影同规格，读起来像并列模块。修法：历史命令卡头部加 eyebrow「会话历史」或缩窄为右栏（在 ≥1200px 视口与终端并排 7:5），消除「两张等宽卡上下叠」的呆板节奏。

### 10. 项目设置（light-settings / dark-settings）

**现状判读**：双栏（左表单卡 / 右两张信息卡），表单 label 上置、字段满宽，节奏规整；「保存设置」主按钮位置正确。

**问题**：
- **P2｜占位符当示例文本滥用**：生产目录输入框占位 `/Users/you/repos/my-game（可选）` 是全页唯一斜体假路径，与下方「当前生效/管理数据」两行真路径（mono 可复制）形成真假路径同屏。修法：占位改为抽象示例 `可选，留空使用默认管理目录`。
- **P2｜「归档项目」danger 按钮孤悬右栏卡底**：右栏「项目状态」卡里统计行是左轴 label/value，「归档项目」红 outline 按钮突然右对齐贴卡底角，与卡内其他元素无对齐关系。修法：按钮改左对齐、与统计行同间距（`margin-top: 12px`），或移出卡片做页级 danger 动作。

### 11. 全局配置（light-global / dark-global）

**现状判读**：顶部三卡（界面/DSH 路径/DSH 服务）+ 下方多张满宽卡，卡片间距一致。整页 4236px 长但每卡有明确标题，眯眼测试仍能分段。

**问题**：
- **P2｜顶部三卡高度不齐**：「界面」卡（滑杆+配色+缩放说明 ~320px）与「DSH 服务」卡（两按钮+一行说明 ~180px）底缘参差，三卡顶部对齐底部散开。修法：三卡 `align-items: stretch` 之下给「DSH 服务」卡补一段弹性空白或把「升级并重启」danger 区压到卡底（`margin-top: auto` flex 布局）。
- **P2｜「升维并重启」danger 与「检查更新/重启 DSH」同排三种按钮语言**：同一卡内 outline×2 + danger×1 横排，danger 未隔离。修法：danger 按钮独占一行或右移，间隔 ≥16px。

### 12. 进化提案（light-evolution / dark-evolution）

**现状判读**：两弹层同骨架（eyebrow+标题 / 表单双列 / footer 取消+主按钮），遮罩 `--overlay` 亮度合适，弹层阴影 `--shadow-3` 层级正确。

## 跨页面一致性问题

1. **字号阶梯**：`--fs-display 24 / title 18 / body 15 / small 13 / caption 12` 在全部截图中执行到位，未发现页内自造字号；这是全站最强的一致性资产，修任何页都不得引入阶梯外字号。
2. **间距节奏**：卡内 padding、卡间距、组间距基本落在 8pt 网格（16/24）；唯一破节奏的是群聊气泡间 44px 级大间距（见 §1 修法）与任务面板组间 ~60px（受 D-60 空白问题影响）。
3. **卡片圆角/阴影**：圆角统一 10-12px、`--shadow-card` 一致；弹层 `--shadow-3` 一致。无问题。
4. **状态色语义**：green 在「成员卡状态文字」（正文用色，light 不达标）与「任务完成 icon」（图形用色，无问题）两处语义强度不同——定一条规则：**语义色永远不做 <15px 正文颜色，只做点、底、边框**。star/amber 同理（light 3.15:1）。
5. **空态样式**：`empty-state`（记忆/进化/历史命令）与 `side-empty`（侧栏）两套并存但各自内部统一，可接受；建议长期收敛为「页内 empty-state + 侧栏 side-empty」两种，不再新增第三种。
6. **mono 使用**：路径/编号/model 名用 mono 一致；唯 usage 分项目行把项目 id 也当标签输出（§8），违反「id 是元数据不是标签」的隐性规则。
7. **导航框架**：全局视图（bots-overview/usage/global）无 tab 条、项目视图有 tab 条、solo 视图有 SOLO_NAV——三套框架本身成立；唯一越界是 evolution 在项目上下文渲染了项目 tab 条（§12）。
8. **终端页双主题策略**：console 井「双主题都暗」策略正确，但 dark 下的面间对比失守（§9），是唯一一处「同一 token 在两主题下表现倒挂」的地方。
